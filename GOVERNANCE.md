# Governance

Feedbacks is maintained by Softinator with community contributions. Maintainers review changes, manage releases and make final decisions about architecture, scope and security.

Routine fixes are decided in pull-request review. Larger changes should begin with an issue that states the problem, alternatives, compatibility and operating cost. Decisions and their technical reasons should remain visible in the issue or pull request. Security details stay private until coordinated disclosure.

Contributors may become maintainers through sustained, constructive work and an invitation from the existing maintainers. Repository administration is separate from authorship. Access is granted according to responsibility and may be removed when it is no longer needed.

The open-source repository contains the application, extension and public website. Deployment credentials, customer data and organization-specific operational records belong in private infrastructure repositories. Hosted operations use the same release artifacts; changes to common behavior should be developed here.

Releases use semantic version numbers, with compatibility changes documented explicitly while the project remains at 0.x. Public roadmap items are proposals, not delivery commitments. No contributor is expected to provide unpaid support on demand.
