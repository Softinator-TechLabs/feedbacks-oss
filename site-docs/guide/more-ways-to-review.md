# More ways to bring feedback together

Start with screenshots and recordings. Enable these additional workflows when your project needs them; they are part of the same Apache-2.0 product.

## Guest review

Invite a client into one discussion with a scoped guest link, or enable project guest submission for new feedback. Choose the access and expiry deliberately. Guests see what their link permits, not your whole team workspace.

[Guest discussion and project submission](/reference/manual/review-workflow#invite-a-guest-to-one-discussion)

## Documents

Upload a PDF or image as a project document. Review its pages and discuss points alongside website feedback, with project authorization applied to the document and its evidence.

[Review a PDF or image](/reference/manual/review-workflow#review-a-pdf-or-image)

## Widget and surveys

The optional website widget collects text feedback from a site you control. It does not silently capture screenshots or browser recordings. Project surveys can collect NPS and written responses when enabled.

[Website widget](/reference/manual/review-workflow#add-the-website-widget) · [Surveys and NPS](/reference/manual/review-workflow#run-an-opt-in-survey)

## Scheduled QA

Enable scheduled checks for eligible public project pages. Review run history and visual baselines; inspect findings before deciding what needs a fix. This is a bounded public-page check, not a promise to test every authenticated flow.

[Scheduled QA and visual baselines](/reference/manual/scheduled-qa)

## Native apps and webhooks

The iOS and Android modules let a host app pair a reviewer device and send screen feedback to the same server. They are developer integrations, not standalone App Store apps.

Signed project webhooks notify your own HTTPS receiver about thread activity. Payloads identify events and revisions without sending thread text or screenshots. API, MCP and CLI provide authorized reads and writes when your integration needs them.

[Native mobile SDK](/reference/manual/mobile-sdk) · [Signed webhooks](/reference/manual/webhooks) · [API and CLI](/reference/api-cli)

## Organize the work

Use assignments, exact work-status filters, categories, tags, saved views and individual point progress. Link delivery evidence and verify the outcome before resolving. [Work through a review queue](/guide/review-feedback).
