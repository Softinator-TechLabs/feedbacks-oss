# Find the work that needs your attention

Ask Codex or Claude to review your Feedbacks queue through MCP. Assigned work, top-priority flags, saved priorities and planned dates help your agent suggest what to tackle next, with the evidence to explain why.

## Start with your queue

The portable review skill finds your assigned work and respects the team's saved priority and dates. Future and Later tasks stay distinct from work ready to begin. For a broad backlog request, the agent offers eligible tasks and asks which to start; you can also request a specific thread or agree a batch.

Top priority is an explicit team signal. Approved reviewer expertise and importance weights can add context when your key permits access; they do not replace human planning or grant permission to act.

## Give the agent useful context

The owner prepares project access, published context and approved instructions. Add responsibilities, design constraints and acceptance criteria where useful. Captured comments remain evidence, separate from approved guidance; private member notes are excluded from normal agent context.

## From selection to a verified change

1. Choose the work in your agent, or use **Copy task for agent** on a thread.
2. The agent reads the selected evidence, checks existing workers and claims the agreed work.
3. It implements the change, runs the relevant checks and records the result.
4. Resolve verified points; leave unfinished work and required reviews visible.

Agents can read compact summaries first, then selected screenshots, recordings or event ranges. Use [debug bundles](/guide/debug-bundles) for portable evidence.

## Connect your own agent

MCP, the HTTP API and JSON CLI share project authorization. Connecting MCP or assigning a task does not launch a background agent. Your chosen agent works when instructed; model subscriptions are separate, and GitHub is optional.
