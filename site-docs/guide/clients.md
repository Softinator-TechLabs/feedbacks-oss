# Client guide: show the team what needs to change

Feedbacks helps your team and its coding agents understand your request. You point to the problem and describe the change. Your team handles the server, projects, GitHub and AI setup.

## Ask your team for review access

For browser capture, ask for the team's Feedbacks address, your sign-in access and the project or website to review. Then follow [install, pin and connect](/guide/chrome-extension#install-pin-and-connect). Your team already runs the server; you do not need your own.

Your team may instead send a scoped guest review link when that feature is configured. Open the supplied link and use the review controls available there. A guest link is not a server installation, an extension pairing or an MCP credential. Ask the team for extension access if you need the browser capture workflow below.

## Leave one clear request

1. Open the website and click the pinned Feedbacks extension.
2. Right-click the element you mean. Write what is wrong and what you expected.
3. Choose **Save point**. Add more points if needed.
4. Choose **Review & send**, check the screenshots and notes, then **Send feedback**.

For example: “On my phone, this button overlaps the total. Please leave enough space so I can read the amount.” You do not need to name a code file or explain how to implement it.

A saved point is still a local draft until you send it. Inspect sensitive information before sharing screenshots.

## Follow the result

Open the resulting feedback thread on the team server. Reply there if the developer needs clarification. When a fix is ready, open the page or preview they provide and check your original request again. Tell the team what is correct and what still needs work.

You do not need MCP or an AI subscription to submit feedback. The developer connects their own agent and verifies its changes.
