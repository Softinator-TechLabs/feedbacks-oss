# Start here

Feedbacks prepares visual website feedback for AI-assisted UI changes and bug fixes. Follow the [complete setup flow](../site-docs/guide/getting-started.md): team server → extension → projects and people → personal MCP connection.

Choose the [client guide](../site-docs/guide/clients.md), [extension installation and capture guide](../site-docs/guide/chrome-extension.md), [owner setup](../site-docs/guide/team-setup.md), [DevOps installation](../site-docs/guide/self-host.md) or [resolving developer guide](../site-docs/guide/mcp.md).

For a new installation, follow [self-hosting](self-hosting.md). For an existing team workspace, ask its owner for the server address and an invitation. Feedbacks does not have public self-service registration.

Sign in, open a project and review its feedback. Owners manage members and allowed website origins. Project maintainers manage custom categories and tag colors in **Project settings → Categories & tags**; feedback rows show those labels directly. Install the [browser extension](extension.md) to capture pages and submit comments. Use [agent setup](agent-setup.md) for MCP access with a scoped credential.

In **People**, select one person to edit their account or project access. Expertise categories give agents context, while advanced feedback weighting changes preference summaries and does not grant permission. Disable an account before removing it from the People list. Owners can show removed accounts and restore them; restoration leaves login disabled until explicitly enabled. After creating a user, **Copy login and setup message** prepares a private note with the login and Setup links. After setting a new password for an existing person, **Copy password and login link** becomes available only after the save succeeds; send it privately and clear it afterward. New agent keys show their last four characters in Account so you can identify them; older hashed keys cannot recover that ending.
